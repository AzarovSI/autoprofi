# Проверка комплекта восстановления, 07.10.2026

## Что проверено

- Архив распакован в отдельный каталог /tmp, вне исходного проекта.
  Использован CPython 3.12.13, отдельное venv без системных Python-пакетов.
- Установка всех 23 runtime-пакетов прошла из recovery/wheels с --no-index
  и --require-hashes. pip check: без конфликтов.
- В отдельной локальной PostgreSQL 18 восстановлена структура рабочей
  PostgreSQL 17.10 (только schema, без пользовательских/коммерческих данных).
  Добавлены синтетический пользователь и минимальные служебные записи.
  Рабочая БД использовалась только для чтения структуры.
- Bootstrap проверил целостность архива и структуру БД, создал ключ и запустил
  настоящий app.main:app через uvicorn. Подмена app.db/API при проверке сервера
  не использовалась.
- 15 HTTP проверок: health, login/auth, ABC, РНП WB/Ozon, Юнит-экономика WB/Ozon,
  цены, продажи, склады WB/Ozon, справочник, пользователи и оба ценовых
  XLSX-экспорта. Все проверенные GET-ответы: HTTP 200; login успешен.
- Playwright: реальный вход, переходы по всем разделам. Продажи и справочник
  дождались собственных контролов. ABC при пустой базе показывает штатное
  «Нет данных за выбранный период». Цены и пользователи отображаются.
  В первой браузерной проверке ошибок JavaScript и ответов 4xx/5xx нет.
  Screenshot desktop 1440x1000 проверен; mobile 375x900 сохранён.
- Полный набор backend-тестов в распакованном проекте под Python 3.12:
  98 passed, 4 skipped, 85 subtests passed. Тестовые библиотеки
  pytest/httpx/httpcore установлены отдельно только для тестового прогона;
  они не нужны для работы сайта и не входят в runtime lock.

## Выявленные особенности и решения

- Переносной Python, вызываемый через симлинк, некорректно определял home
  при создании venv. Bootstrap теперь сначала разрешает симлинк интерпретатора.
- Одной структуры БД недостаточно: нужны также служебные записи миграций/Pi.
  Предварительная проверка теперь отсекает неполное восстановление до старта.
- Пустая тестовая БД не моделирует весь объём и все комбинации рабочих данных.
  Полное восстановление пользовательского дампа в эту среду не выполнялось.
  Наличие всей истории зависит от внешнего резервного копирования PostgreSQL.
- Docker недоступен в среде: альтернативный Docker-шаблон не тестировался.
  Основной проверенный путь: recovery/run.py на Linux x86_64 / Python 3.12.
- Домен, DNS, HTTPS, ОС и доступность БД являются внешней инфраструктурой,
  а не содержимым резервной копии кода.

## Безопасность и воспроизводимость

- Реальные DB_DSN/SECRET_KEY, старые документы с секретами, .git, config.json,
  runtime и пользовательские отчёты не входят в allowlist сборщика.
- BACKUP_MANIFEST.json перечисляет каждый включённый файл и SHA-256.
  Bootstrap проверяет файл до установки зависимостей и доступа к БД.
- Рабочий сайт и рабочие данные этой задачей не изменялись.
