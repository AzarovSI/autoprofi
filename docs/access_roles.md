## Решения владельца (12.10.2026)

1. **«Ограничения данных» заполнены** (лист в xlsx):
   - площадки — Адм, РОП, Продакт, Маркетинг видят все три; Менеджер WB/OZ/YA — только свою;
     Ассистент — ни одной (его загрузки заданы отдельными функциями, РНП — см. п. 2);
   - «видит все товары» — все роли (фильтр «только свои товары» пока не нужен);
   - блок «Финансы» (себестоимость, прибыль, реклама) в xlsx заполнен, но **из схемы убран** —
     см. «Согласованная схема».
2. **Менеджеры в РНП видят все площадки — так задумано**, ограничивать будем постепенно.
3. **Статус товара по-разному в разных местах — так задумано:** в справочнике «Товары» — массовая
   обработка (менеджерам и Ассистенту можно), в отчётах — оперативная работа (не всем).
4. **РОП добавляет пользователей, но не меняет и не удаляет — верно.**
5. **Правила аномалий — пока как в матрице;** если раздел аномалий уберут, права поправить.
6. **Справочник «Товары» площадками роли не ограничивается** (изменено 12.10.2026, было —
   ограничивать): это общий раздел, как «Цены» — кому он доступен, работают со всеми площадками,
   а лишнего сделать не могут (действия — по функциям).
7. **Права остаются подробными (99 функций).** Вариант свернуть их в 21 право обсуждался и
   отвергнут — подробные понятнее. Удобство — за счёт интерфейса карточки роли (см. ниже).
8. **Администратор может назначать роль «Администратор»** — при добавлении пользователя
   и при изменении. Владельца нельзя снять с роли «Администратор» и удалить.
9. **РОП при добавлении пользователя выбирает любую роль из справочника, кроме
   «Администратора»** (вариант А). Роль уже созданного сотрудника РОП не меняет.
10. **Скорость не должна пострадать** (вопрос владельца, у 1С права замедляют отчёты):
    права роли — в памяти сервера, проверка до запроса к данным, без фильтров по строкам;
    кэш ответов общий для всех ролей (себестоимость убирается из готового ответа, а не
    считается отдельно для роли). На этапе 5 — замер открытия разделов до и после под разными
    ролями, цифры показать владельцу. Сделано на этапе 2 так: права и площадки читаются тем же
    запросом к БД, которым сервер и раньше на каждом действии проверял пользователя, — лишних
    обращений к БД нет, изменённые права действуют со следующего действия.

## Согласованная схема (12.10.2026)

**Настройка:**
- Пользователь → одна роль из списка → готово.
- Новая вкладка «Роли» (рядом с «Пользователями»): список ролей с числом функций и сотрудниками
  в каждой; карточка роли — сверху блок «Площадки» (WB / Ozon / Яндекс), ниже разделы сайта
  (сворачиваются), у раздела галочка «Доступ к разделу» (снята — раздел пропадает из меню,
  функции серые), внутри — подробные функции по вкладкам (как в xlsx), «Отметить / снять всё»
  на разделе и группе, «Сохранить» — права меняются у всех сотрудников роли без перезахода.

**Правила (все подтверждены владельцем):**
1. Роль «Администратор» нельзя изменить или удалить — всегда все права; владелец
   (`azarov.si@gmail.com`) всегда администратор.
2. Менять роль у пользователя и настраивать роли — только администратор. РОП может открыть роль
   и посмотреть её права — **только просмотр**.
3. Права проверяет сервер, интерфейс только скрывает (закрыть и дыру справочника товаров).
4. 8 ролей создаются по xlsx; новые роли — копированием существующей.
5. Новая функция сайта при будущих доработках появляется в карточке роли, по умолчанию включена
   только администратору.
6. Новые таблицы БД (роли с площадками, права ролей, роль у пользователя) — миграция рабочей БД,
   схема показывается владельцу и согласуется отдельно.

**Площадки:**
- Площадки роли ограничивают вкладки и данные площадок в юнит-экономике, продажах, складах,
  справочнике «Товары», загрузках — и на сервере (подставленный вручную запрос чужой площадки
  не проходит).
- Исключения: **РНП** — пока все видят все площадки (ограничивать постепенно);
  **«Товары»** — площадки не ограничивают (общий раздел, решение 6);
  **«Цены»** — площадки не ограничивают: если раздел доступен, видно всё (цены всех площадок —
  место для сравнения), кроме себестоимости в прайс-листе.
- «Сводная» в продажах и ABC по площадкам — по матрице (у ролей, которым они отмечены, все
  три площадки).

**Себестоимость:** ограничивается **только в прайс-листе** — функция «Показать себестоимость»
(Адм, РОП, Продакт). В юнит-экономике и складах себестоимость видна всем, кому открыт раздел.

**Убрано из схемы (решение 12.10.2026):** блок «Финансы» (себестоимость, прибыль и маржа,
реклама и ДРР) и «Видит все товары / только свои» — сейчас никого не ограничивают; вернуть,
когда понадобится. Свёртка 99 функций в 21 право — отвергнута (подробные права понятнее).

## Хранение ролей (этап 1, схема согласована 12.10.2026)

Миграция `migrations/2026_10_12_access_roles.sql`, выполняется на старте сайта
`app/permissions.py:migrate()` (по образцу `daily_pi.migrate()`: advisory lock, одна транзакция,
запись в `app_schema_migrations`). К рабочей БД применится при выкладке.

| Таблица / колонка | Что хранит |
|---|---|
| `app_roles` | `id`, `name` (уникально), `is_admin` (роль «Администратор»: всегда все права, такая роль одна — уникальный индекс), `marketplaces` (набор из `Wildberries`, `Ozon`, `Yandex`, проверка CHECK), `created_at` |
| `app_role_permissions` | `(role_id, permission)` — только разрешённые функции: есть строка — можно. При удалении роли её права удаляются (CASCADE). У администратора строк нет |
| `app_users.role_id` | роль пользователя; роль с сотрудниками удалить нельзя (RESTRICT). Старая колонка `role` (`admin`/`user`) остаётся для отката на прежнюю версию; новый код будет дописывать в неё `admin` для роли «Администратор», `user` — для остальных |

- Миграция создаёт 8 ролей из xlsx с площадками с листа «Ограничения данных» и 374 права
  (РОП 92, Продакт 65, Маркетинг 49, Менеджеры WB/OZ 49, Менеджер YA 32, Ассистент 38).
- Каталог 99 функций — `app/permissions.py:FUNCTIONS` (№, код, раздел, вкладка, функция, тип,
  описание — как в xlsx). Коды — в колонке «Код» матрицы ниже. Новая функция добавляется в конец
  каталога; в БД её нет ни у кого, поэтому она доступна только администратору.
- `role_id` миграция ставит только владельцу (`OWNER_EMAILS`) — роль «Администратор»; остальным
  роли назначает владелец (этап 5), отдельной согласованной записью в рабочую БД при выкладке.
- Проверено 12.10.2026: тесты `tests/test_access_roles.py` (каталог = xlsx, роли и права = xlsx,
  повторный запуск ничего не меняет, ограничения); миграция на копии структуры рабочей БД

## Как сервер проверяет права (этап 2, сделано 12.10.2026)

Код: `app/auth.py` — `load_user` (пользователь + роль + права + площадки одним запросом),
`can`, `check`, `require(код…)`, `require_tab(раздел)`, `require_tabs`, `check_marketplace`;
коды функций и разбор площадки — `app/permissions.py`. Отказ — 403 с названием функции
(«Нет доступа: Цены → Показать себестоимость») или площадки.

- **Вход:** без роли или без функции «Вход на сайт» — 403 и при входе, и на любом действии
  (снятие права действует сразу). Владелец (`OWNER_EMAILS`) — всегда администратор.
  `/api/auth/me` и ответ входа отдают `role_name`, `is_admin`, `permissions`, `marketplaces`.
- **Всем вошедшим:** `/api/metrics/weeks` (сайт вызывает при старте) и `/api/catalog/tree`
  (списки статусов и менеджеров для фильтров всех разделов).
- **Вкладки площадок** (юнит-экономика, продажи, склады) — функция вкладки и площадка у роли.
  **РНП** — только функция вкладки (площадки не ограничивают). **Цены** и **Товары** —
  площадки не ограничивают.
- **Загрузки файлов** — только своя функция, площадки роли не проверяются: у Ассистента
  площадок нет, его загрузки заданы функциями (решение 1).
- **Сводные данные нескольких площадок** (`/api/rnp/tree_cross`, `/api/metrics/mp_compare`) —
  вкладки и площадки Ozon и WB. «Сводная» в продажах — функция «Вкладка „Сводная“».
- **Себестоимость:** в ответе прайс-листа поля `cost`/`cost_date` пустые без функции
  «Показать себестоимость»; выгрузки с `show_cost` без неё — 403.
- **Справочник «Товары», сохранение товара** (`PUT /api/catalog/items`): площадки не проверяются;
  новый артикул (нет в `catalog_items`) — «Добавить товар»; только статус (так шлют РНП,
  юнит-экономика и ABC) — любая из функций «Изменить статус товара» или правка карточки;
  остальное — правка карточки. Дыра «добавить / загрузить без прав» закрыта.
- **Журналы загрузок** (`/api/upload/history?kind=`): по разделу набора (РНП, юнит-экономика,
  склады); `all` и неизвестный набор — нужны журналы всех трёх разделов.
- **Комментарии РНП:** свой — «Изменить / удалить свой», чужой — «… чужой».
- **Пользователи:** функции раздела; роль «Администратор» назначает и роль сотрудника меняет только
  администратор; владельца нельзя снять с роли, сменить ему e-mail (по нему он владелец) и удалить.
  Роль пока выбирается из `admin`/`user` — выбор из справочника ролей будет на этапе 4.
- **Старые эндпоинты** `/api/metrics/*` и `/api/trend/*` (в меню их нет) — как данные
  юнит-экономики; Яндекс в них = Ozon, как и в самих роутерах.
- Проверено: `tests/test_access_checks.py` — каждая из 8 ролей × 95 действий сервера: 403 ровно
  там, где по матрице нет функции или площадки; плюс вход без роли, владелец, права без перезахода,
  правила комментариев, себестоимости и пользователей.

**До выкладки важно:** пользователь без роли на сайт не войдёт (кроме владельца). Перед выкладкой
всем сотрудникам должны быть назначены роли (этап 5).

- **Журнал остатков Ozon** («Склады → Загрузка данных»): раньше сайт запрашивал набор `ozon_stock`,
  которого сервер не знал, и получал журнал всех загрузок. С 12.10.2026 набор есть
  (`period_kind = 'ozon_stock'`), право — «Журналы загрузок остатков и себестоимости».

## Интерфейс по правам (этап 3, сделано 12.10.2026)

Интерфейс только прячет — проверяет сервер. Код: `static/js/app.js` — `App.can(код)`,
`App.hasMp(площадка)`, `App.canTab(раздел, площадка)`; права берутся из `/api/auth/me` при каждом
открытии сайта (изменённая роль подхватывается обновлением страницы, без перезахода).

- **Меню** — по функциям «Открыть раздел»; недоступный раздел открывает первый доступный.
  Без роли — на экране входа причина «Нет доступа к сайту…».
- **Вкладки площадок** — функция вкладки и площадка роли (РНП и ABC — только функция;
  справочник «Товары» — все три вкладки при функции «Вкладки площадок…»).
  «Сводная» в продажах — своя функция. Недоступная выбранная вкладка заменяется первой доступной.
- **«Загрузка данных»** (РНП, юнит-экономика, цены, склады) — вкладка видна по функции
  «Открыть вкладку» (в ценах и складах — если есть хоть одна загрузка или журнал); карточки
  загрузок и журналы — по своим функциям (`views.js:applyUploadRights`). Подвкладки: если у роли
  есть загрузки — только подвкладки с ними, иначе — с журналами.
- **Без права — неактивно, а не скрыто:** статус товара в РНП, юнит-экономике и ABC; строки
  справочника «Товары» (поля неактивны, «Сохранить» скрыта); селекты справочника складов.
  Скрыто: кнопки выгрузок и загрузок, «показать себестоимость», окно юнит-экономики, ссылка на
  карточку товара, «Аномалии» и настройка порогов, добавление и правка комментариев, правка
  цены и плана в ячейке (двойной клик не работает), инциденты складов, кнопки складов,
  кнопки «Пользователей» и роль «Администратор» в форме (у не-администратора).
- Функции навигации («Период, поиск, фильтры…» в разделах) в матрице совпадают с доступом к
  разделу или вкладке, отдельно в интерфейсе не проверяются; в справочнике «Товары» —
  проверяются (`catalog.table`).
- Проверено 12.10.2026 в браузере (Playwright, локальный сайт на копии БД от 11.10.2026,
  `autoprofi_access_check` на Mac, по проверочному пользователю на роль): меню, вкладки, карточки
  загрузок и кнопки у всех 8 ролей совпадают с матрицей; при обходе всех разделов и вкладок —

## Вкладка «Роли» (этап 4, сделано 12.10.2026)

Раздел «Пользователи» → вкладки «Пользователи» и «Роли». Код: `app/routers/roles_router.py`,
`static/js/views.js` (`renderRolesList`, `renderRoleCard`), стили `.role-*` в `static/css/app.css`.

- **Смотреть** роли — всем, кому открыт раздел «Пользователи» (РОП — только просмотр);
  **менять** — только администратору. Роль «Администратор» не меняется и не удаляется.
- **Список ролей:** площадки, «N из 99», сотрудники; «Настроить / Открыть», «Копировать»,
  «Удалить» (роль с сотрудниками удалить нельзя — сообщение «сначала назначьте им другую роль»).
- **Новая роль — копией** существующей (площадки и права). Копия администратора — обычная роль
  со всеми 99 функциями. Названия уникальны без учёта регистра.
- **Карточка роли:** название, блок «Площадки» (WB / Ozon / Яндекс), разделы как в xlsx
  (сворачиваются): у раздела галочка «Доступ к разделу» (у «Входа» — «Вход на сайт»; снята —
  раздел серый, пропадает из меню), счётчик «N из M», «Отметить всё / Снять всё»; внутри —
  функции по вкладкам («отметить / снять» у группы), тип и описание как в xlsx.
  «Сохранить» — права меняются у всех сотрудников роли со следующего действия; своя роль —
  меню обновляется сразу. Несохранённые изменения помечаются, «Отменить изменения» — возврат.
- **Пользователи:** роль — из справочника ролей (`role_id`); без роли — плашка «Нет роли».
  Роль «Администратор» в списке — только у администратора; у остальных выбор роли при правке
  неактивен. Колонка `role` (`admin`/`user`) дописывается по роли — для отката.

  удаление, права сотрудников сразу, роль «Администратор», проверки, назначение ролей
