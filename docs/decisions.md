# Решения

Обновлено: 15.10.2026.

Источники: выгрузка Perplexity от 07.10.2026 (`docs/archive/perplexity_export_20261007/`),
дословные сообщения владельца из `01_agent_instructions.md`, сверка с кодом.
Ссылки на код даны в виде «файл:функция» и проверены grep'ом 07.10.2026.
Хронология и инциденты — в `docs/history.md`, открытые вопросы — в `docs/backlog.md`.
Если решение здесь расходится с кодом, верить коду и спросить владельца.

## Действующие архитектурные решения и почему

### Данные и загрузка

- **Ключ товара — артикул продавца, а не SKU площадки.** Данные приходят из разных
  отчётов, и сводить их можно только по общему справочнику.
  Где: `app/util.py:canon_article`.
- **Только файлы, без API маркетплейсов.** У MPPROFIT в текущем процессе нет API,
  а менеджеры начинают утро с выгрузки отчётов из кабинетов.
- **Колонки ищутся по имени заголовка, лист — по заголовкам.** Выгрузки меняются:
  06.07 MPPROFIT вставил колонку «Заказы, руб.», и позиционная проверка сломалась.
  В WB-отчёте встречается опечатка «Цена со скидки». Перестановка колонок допустима.
  Где: `loader_core.py` (`WB_REQUIRED`), `ozon_daily_loader.py` (`OZ_DAILY_REQUIRED`),
  `price_upload.py:_parse_daily_report`.
- **Чтение Excel через `python_calamine`, openpyxl — только где нужен формат ячейки.**
  openpyxl не открывает файлы 1С и WB, потому что в архиве `SharedStrings.xml`.
  calamine не отдаёт формат ячейки. Где: `wb_stock_loader`, `cost_loader`,
  `wb_daily_loader`, `wb_reviews_loader` (XLSX через openpyxl, старый не-ZIP через calamine),
  починка архива в `ozon_stock_loader:_open_workbook`.
- **Проценты хранятся долями 0..1, масштаб берётся из формата ячейки.** Нужна единая
  конвенция для фронтенда, это подтвердили инциденты 28.07 (CTR) и 07.10 (СПП).
  CTR = Σклики / Σпоказы, а не среднее готовых процентов.
  Где: `wb_ads_loader`, `ozon_ads_loader`, `wb_reviews_loader`.
- **Повторная загрузка заменяет данные своего дня или ключа.** WB и Ozon задним числом
  правят прошлые периоды, а менеджеры грузят файлы с перекрытием дат.
  Дневные загрузчики удаляют и вставляют строки по датам файла.
  Ценовые отчёты делают upsert по ключу дата + артикул + МП.
- **Перезапись дня сохраняет поля других загрузчиков (`PRESERVE_COLS`).** Одну дневную
  строку заполняют 3–5 разных отчётов. Где: `ozon_daily_loader`, `wb_daily_loader`,
  `ya_daily_loader` (константа `PRESERVE_COLS`).
- **Запись в БД только пакетная.** Каждое обращение к Yandex Cloud стоит десятки
  миллисекунд, построчная запись давала ошибку 524.
  Где: `db.py:execute_values`, `db.py:transaction`, `price_history.py:sync_uploaded_prices`,
  `UPDATE … FROM (VALUES …)` в загрузчиках.
- **Каждая загрузка пишется в `report_uploads`, автор — через `current_setting`.**
  Так не пришлось править 23 INSERT в 16 загрузчиках: колонка `uploaded_by_user_id`
  берёт значение по умолчанию из `app.uploader_id`. Где: `upload_router.py:_set_uploader`.
  Миграция этой колонки применялась вручную 09.09, файла миграции в репозитории нет.
- **Общий склад 1С (`stock_daily`) пишет только товары справочника и не расширяет РНП.**
  В файле 1С примерно вдвое больше товаров. Регрессия 24.09 показала, к чему ведёт
  расширение состава. Где: `ozon_stock_loader`, `rnp_sales_router.py:_build_rnp_sales_tree`.
- **Три контура остатков не смешиваются.** Остаток МП в дневном РНП, общий склад 1С
  и складская оценка (`ozon_stock_daily`, `wb_stock_daily`) грузятся разными отчётами
  и имеют разный смысл.
- **MPPROFIT WB сверяется с ИТОГО до записи (14.10.2026).** Колонка, найденная по имени,
  может оказаться не той (секции «Продажи» и «Налог» в строке 4 годами подменяли метрики).
  Расхождение Σ строк с ИТОГО отклоняет загрузку; исключение — заказы (ИТОГО MPPROFIT
  по заказам бывает неверным, 04–06.2026). Строки только со штрихкодом доразносятся к товару.
  Где: `loader_core.py:check_wb_report`, `merge_orphans`. С 14.10.2026 так же для Ozon
  (`check_oz_report`): разница с ИТОГО по выручке/удержаниям/выплате/прибыли относится к строке
  общих удержаний, она обязана сходиться; отрицательные общие удержания не обнуляются.
- **WB «(с рекл.)» — только за периоды с рекламой по товарам (14.10.2026).** В месяцах, где
  у MPPROFIT нет рекламы по товарам (06.2024–01.2025, 03–06.2025), берутся показатели без
  «(с рекл.)», реклама остаётся в общих удержаниях. Других данных за эти месяцы у владельца нет.
  Где: `abc_router.py:WB_NO_ADS_MONTHS`.
- **План продаж не заводит товары (19.10.2026, решение владельца).** Товар появляется
  в системе из справочника или из отчётов площадки. Импорт плана сверяет артикулы со
  справочником этого МП: неизвестный артикул — отказ всего файла со списком. Причина:
  новые артикулы в шаблоне плана (RPT-120…RPT-50, опечатка EDG25-05B вместо EDG25-50B)
  попадали в «Продажи, шт.» как «(без категории)», а в «Товарах» их не было.
  Где: `sales_router.py:_missing_in_catalog`, `plan_import`, `plan_cell`.

### Производительность и кэш

- **Пул соединений вместо параллельных запросов.** Новое TLS-соединение стоило около
  1,9 с на каждый запрос. Параллельные запросы через `ThreadPoolExecutor` оказались
  медленнее и были отменены. Где: `db.py:_get_pool` (`psycopg_pool`, 2–20 соединений),
  комментарий в `catalog_router.py:tree`.
- **Кэш ответов в памяти процесса: namespace, `bump()` и TTL.** Дерево РНП весит
  около 13 МБ и собиралось 6–9 секунд. Инвалидация — повышением версии namespace
  при каждой записи, TTL 1 час страхует, если сброс где-то пропущен. Где: `app/cache.py`.
- **Ключ кэша РНП собирается из нормализованных параметров.** В него входят МП
  (`wb` и `wildberries` дают один ключ), версия формата (`v8`) и ревизия Pi.
  У каждого МП свой namespace. Где: `rnp_sales_router.py:rnp_sales_tree`,
  `rnp_sales_router.py:_price_revision`, сброс — в `upload_router`.
- **gzip и `no-store`.** Сжатие уменьшает ответ дерева примерно в 10 раз. `index.html`
  и выгрузки XLSX не кэшируются, чтобы не отдавать старый код и старые отчёты.
  Где: `main.py` (`GZipMiddleware`, маршрут `/`), `sales_router`, `prices_router`.
- **Ускорение РНП и юнит-экономики (11.10, согласовано владельцем).** Дерево РНП на период
  по умолчанию считается заранее в фоне (`app/rnp_warmup.py`, `RNP_WARMUP=1`) и хранится
  в кэше уже сжатым; одно дерево не собирается параллельно; ответы компактные
  (8 значащих цифр, не меньше 4 знаков после запятой — экран совпадает до символа);
  статика со штампом `?v=` кэшируется браузером на год. Где: `app/fastjson.py`,
  `rnp_sales_router.py:rnp_sales_tree`, `main.py:StampedStaticFiles`.
- **Защита от гонки запросов при переключении МП.** Поздний ответ другой вкладки
  отбрасывается. Где: `static/js/views.js:rnpsLoad` (`_reqSeq`).

### РНП, статусы, склады

- **Акции товаров в РНП — отметки без расчётов (23.10.2026, решение владельца).** Менеджер
  открывает акцию в окне ячейки (название, вход, плановый выход), может завершить раньше или
  отменить запись. Своя акция у каждой площадки, одна у товара одновременно. В РНП — светлая
  штриховка дней акции и контурная ракета у монеток; журнал со всей историей — для статистики.
  Права — как у комментариев, журнал — Администратор, РОП, Маркетинг. Выгрузки и влияния на
  расчёты нет. Где: `rnp_promos_router.py`, `views.js:rnpsPromoPaneHtml`, `rnpsPromoJournal`.

- **Статус, менеджер и ссылка хранятся по МП, категории — общие.** На разных площадках
  у товара разные статусы. Правило подтверждено владельцем 06.10: «Товары», РНП
  и юнит-экономика меняют одну запись артикул + МП.
  Где: `catalog_router.py` (`catalog_marketplace`, `catalog_items`).
- **Нераспределённые товары входят в итоги, но не в дерево.** Для дерева нужны
  L1–L3, статус и менеджер этого МП. Статус «-» без заказов, рекламы и остатка МП
  скрыт. У WB пустой статус без активности не вводит товар в РНП (05.10).
  Где: `rnp_sales_router.py:_build_rnp_sales_tree` (`is_undist`).
- **«Требуют распределения» — за выбранный период (16.10, решение владельца).** Сообщение
  показывает только нераспределённые товары с движением в выбранном периоде, их сумму
  (юнит-экономика — продажи, РНП — заказы) и долю от «Итогов». Итоги верные, как раньше.
  Правило одно везде, менеджер обязателен и в галочке «Товаров» (`app/util.py:is_undistributed`).
  Раньше юнит-экономика считала по всем загруженным периодам (месячный WB: 220 вместо 1).
- **Неполный текущий день допустим (24.09).** Показатели дня видны и без файла заказов,
  но день без заказов не входит в базу прогноза и оборачиваемости.
- **Месячные срезы зависят от смысла метрики (26.08).** Рейтинг и отзывы берут последнее
  непустое значение, остатки — строго последний загруженный день, иначе прочерк.
  Где: `rnp_sales_router.py` (`SNAP_LAST_NONEMPTY`, `SNAP_LAST_DAY`).
- **Оборачиваемость считается по скользящему окну 30 дней.** Якорь — последняя дата
  данных, для WB — последний день заказов (03.08, 07.10). Календарный месяц
  в начале месяца давал завышенные значения. Где: `rnp_sales_router.py` (`TURN_WINDOW_DAYS`).
- **ABC: цель — развести ассортимент Ozon и WB (решение владельца 19.10.2026).** Правила «Убрать с этого МП» и
  «Рассмотреть перенос» снимают товар с площадки, даже если он там прибылен, когда на другой площадке он заметно
  сильнее; в «Плане действий» и прогнозе это вывод. Не предлагать убрать эти правила. Где:
  `abc_module.js:makeRecommendation`, пороги — ⚙ (`abc_rules`).
- **ABC считается в браузере по сырым метрикам.** Колонка `abc_profit` из MPPROFIT
  испорчена (22.06). Где: `static/js/abc_module.js:abcClassify`.
- **Инциденты складов — ручные периоды, на склад один открытый.** Нужна история
  инцидентов. Заморозка стоимости Ozon внутри инцидента делается только во фронтенде,
  данные в БД не меняются. Где: `warehouses_router.py:incident_open`,
  `ozon_warehouses_router.py:incident_open`, `views.js` (`frozenByKey`).

### Цены и Pi

- **Прямые ценовые отчёты изолированы от РНП (18.09).** Дата, цена и СПП или соинвест
  берутся из файла. Источники `upload_wb_spp` и `upload_ozon_coinvest` исключены
  из пересчёта по РНП. Где: `price_history.py:recalc_spp_and_buyer_from`,
  `price_history.py:sync_direct_report`.
- **Колонки Ozon (18.09).** Загружаемая цена — «Цена продавца после акций»,
  цена покупателя — «Цена продавца с соинвестом». СПП или соинвест 0 либо пусто
  означает, что товара нет: цена покупателя и СПП записываются как NULL.
- **Базовые цены хранятся с историей, отчёт показывает срез на конец периода.**
  Конец периода — по московским суткам, как у daily Pi (с 12.10).
  Где: `catalog_base_prices_hist`, `prices_router.py:pricelist`.
- **Дата начала действия базовой цены в Excel (12.10, вариант А владельца).** Цена действует
  с этой даты и дальше: более поздние версии заменяются (сценарий «залить с начала месяца»
  должен менять и текущую цену). Пустая дата — с текущего момента. Будущие даты не
  принимаются. Ручная правка ячейки — с момента правки. Где: `prices_router.py:_apply_from`,
  `prices_import`.
- **«Ценовая модель» — справочник средних цен категории (21.10, решение владельца).** Вид и состав — как
  «Прайс-лист», без Pi; три вводимые колонки WB / Ozon / Yandex. История — одна запись на день (последняя
  правка дня), отчёт — срез на конец периода. Excel и себестоимость пока не нужны; тестовые значения листа
  13.10 не переносятся. Где: `price_category_hist`, `prices_router.py:model_category*`.
- **«Ценовая модель»: блоки WB и Ozon — ДРР · Маржа, % · Загружаемая · СПП · Цена категории (21.10, решение владельца).**
  ДРР и маржа плановые, вводятся и хранятся с историей, как цена категории (общая таблица `price_model_hist`).
  Загружаемая = цена категории / (1 − СПП), вверх до рубля. Yandex убран (нет СПП). ДРР и маржа — один знак
  после запятой. Где: `prices_router.py:model_params`, `model_param_set`; `views.js:pricesModelPaintTable`.
- **«Ценовая модель»: сигналы корректировки вместо новых колонок (21.10, решение владельца).** Метка ▲/▼ и подсветка
  в «Загружаемой», когда цена в кабинете отклоняется от расчётной больше порога; подсказка с причиной; счётчик и фильтр
  «требуют корректировки». Пороги ⚙ — свои у WB и Ozon, по умолчанию 5%, общие для всех. Акции пока не учитываются.
  Права раздельные: цена категории (№101), ДРР (№106), маржа (№107), пороги (№108), выгрузка (№109), загрузка (№110).
- **«Ценовая модель»: Excel для массового заполнения (21.10, решения владельца).** Шаблон — видимые строки отчёта;
  пустая ячейка удаляет значение (как в «Прайс-листе»); артикулы не заводятся, сверка со справочником площадки;
  колонки без права не загружаются, остальные — загружаются; ошибочное значение отменяет весь файл.
- **«Продажи, шт.»: период — диапазон месяцев вместо года (15.10, решения владельца).**
  Данные помесячные, поэтому в фильтре сетка месяцев, а не дни. Период может переходить через
  год, по умолчанию — текущий календарный год, общий для всех вкладок. Шаблон плана — строго
  по месяцам периода. Загрузка берёт месяц и год из шапки файла («Январь 2026») и перезаписывает
  только эти месяцы: раньше файл удалял план всего года по своим артикулам. Где:
  `sales_router.py:_period_months`, `_plan_header_months`, `plan_import`; `views.js:bindSalesPeriod`.
- **Дневной Pi хранится в `price_index_daily` и пересчитывается триггерами (21.09).**
  Владелец выбрал хранение, а не расчёт на лету. Значение берётся строго за дату,
  без переноса с прошлых дней. Итог месяца — срез на конец (`daily_pi.month_end`).
  Где: `migrations/2026_09_21_daily_pi.sql` (триггеры на `mp_price_daily`,
  `catalog_base_prices_hist`, `catalog_items`), `daily_pi.py:migrate/load`.
- **«Pi покупатель» = Ozon / WB, одинаковый в обоих РНП (21.09).** Базой сравнения
  всегда служит WB.
- **Pi группы «Продукция ТД АВТОПРОФИ» считается от цены покупателя (14.09).**
  Красный, если меньше 1,15. У остальных групп — загружаемая цена / базовая.
  «Pi покупатель» красный, если меньше 1,03 (17.09). Где: `views.js` (`sp-pi-lo`),
  поле `ap` в `2026_09_21_daily_pi.sql`.
- **Миграции версионные, со startup-блокировкой.** Advisory lock и запись
  в `app_schema_migrations`, чтобы схема и код выкатывались атомарно.
  Где: `daily_pi.py:migrate`.

### Интерфейс и доступ

- **Тема только светлая** (`templates/index.html`, `data-theme="light"`). Цвета площадок:
  WB — фиолетовый, Ozon — синий, Яндекс — янтарный.
- **Юнит-экономика остаётся таблицей.** Дерево и недельная сетка должны читаться быстро.
- **Порядок меню (23.09):** РНП → Юнит-экономика → Цены → Продажи, шт. → ABC → Склады →
  Товары → Пользователи. Период стоит справа, «Загрузка данных» — сразу перед ним.
- **Механизм «только владелец» сохранён, но не используется.** `OWNER_VIEWS` пуст,
  `auth.require_owner` нигде не вызывается. «Склады» открыты всем 30–31.07.
  Где: `app/auth.py`, `static/js/app.js`.
- **Пользователей не удаляют, а отключают (28.10.2026).** Удаление из `app_users` каскадом стирало
  комментарии РНП автора (`rnp_comments.author_id ON DELETE CASCADE`). Отключённый (`disabled_at`) не входит,
  действующий токен перестаёт работать на следующем запросе; записи и имя автора остаются. Себя и владельца
  отключить нельзя. Кнопки удаления и `DELETE /api/users/{id}` нет. Где: `app/routers/users_router.py`, `app/auth.py`.

### Юнит-экономика: «К оплате на р/с» и новая подача (14–15.10.2026)

- **«К оплате на р/с» берётся из отчётов MPPROFIT, а не вычисляется.** WB — «Выплата на р/с (с рекл.)»
  (`wb_payout_with_ads`), Ozon — «Выплата на р/с» (`payout`, реклама уже в удержаниях); в «Итогах» —
  с выплатой строки общих удержаний. Яндекс — пока не выводится (выплату не сверяли).
  Где: `loader_core.py` (колонки), `rnp_router.py:_compute_cell` (`p_payout`).
- **Маржинальности: две, с явными названиями.** «Маржинальность валовая, %» = Прибыль ÷ Продажи, руб;
  «Маржинальность чистая, %» = Прибыль ÷ К оплате на р/с (при выплате ≤ 0 — «—»). Первая формула
  «к оплате ÷ продажи» была ошибкой: это доля выплаты в выручке, она включает себестоимость.
- **WB: логистика и хранение почти нулевые — это верно.** Индивидуальные условия владельца на WB:
  часть расходов несёт площадка. Доли удержаний WB и Ozon напрямую не сравнимы. Нулевые строки WB
  в отчёте не убирать: условия могут измениться.
- **WB «(с рекл.)» — только за периоды с рекламой по товарам**, иначе показатели без «(с рекл.)»
  (см. «Данные и загрузка»). То же правило для «К оплате».
- **Новая подача юнит-экономики — основная во вкладках Wildberries и OZON с 16.10.2026** (решение
  владельца; до этого — тестовые вкладки «WB тест» / «Ozon тест»). Прежняя подача — вкладки
  «… (старый вид)» (№102–103, только администратор) на время, потом удаляется вместе с кодом. Yandex — в
  прежней подаче до доработки загрузчика (нет «К оплате», каскад не сходится). Помесячный вид — отдельное
  право №104 `unit.month`, роли владелец настраивает сам.
  Принципы подачи (утверждены владельцем по ходу правок 15.10):
  - порядок по денежному потоку: воронка → деньги каскадом (Продажи − удержания площадки − без разбивки −
    продвижение = К оплате − себестоимость = Прибыль, маржинальности) → на единицу (только товар,
    тот же каскад на штуку) → структура (только группы/Итоги); блоки разделены линией, без строк-подписей;
  - расходы в каскаде — в процентах (так владельцу удобнее читать), рубли себестоимости — под стрелкой;
  - один набор строк для WB и Ozon: нет показателя — «—», нули не убираются;
  - изменение к прошлой неделе: треугольник ▲/▼ (направление) цветной по смыслу (рост расходов —
    красный), число чёрное без знака и без «%»; нулевые изменения не показываются; числа выровнены по
    правому краю, треугольники — на одной вертикали;
  - вложенные строки правее и приглушены (цвет корневой строки), кроме состава удержаний и блока
    «на единицу»; жирные только Продажи руб / К оплате / Прибыль; подсказки с формулами у всех строк;
  - каскад в тестовых вкладках считается на точных ключах (`p_mp_holds_pct`, `p_ads_paid_pct`,
    `noart_pay_pct`) и сходится до копеек (проверено на всех товарах-неделях 15.10).
  Где: `views.js:testMetricTable`, `T_ROWS`, `tArrowDelta`; `rnp_router.py:_compute_cell`.
- **Отчёт по менеджеру — для бонусов (16.10, решение владельца).** При выборе менеджера юнит-экономика
  и РНП пересчитывают группы и «Итоги» по его товарам на сервере. Общие удержания делятся между
  менеджерами пропорционально продажам колонки (вариант «а»), чтобы Σ менеджеров = магазин.
  Менеджер — текущий (история закреплений «на дату» не нужна и вряд ли понадобится). Точными должны
  быть: Заказы руб, Продажи руб, К оплате на р/с, Прибыль, маржинальность валовая и чистая.
  Где: `rnp_router.py:rnp_tree` (`noart_share`), `rnp_sales_router.py` (`manager`).
