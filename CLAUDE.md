# ТД АВТОПРОФИ — аналитика маркетплейсов

Внутренний сайт компании ТД АВТОПРОФИ (владелец — Сергей Азаров). Около десяти
сотрудников ежедневно загружают Excel-отчёты Wildberries, Ozon, Яндекс.Маркета,
MPPROFIT, 1С и PriceVA и работают с заказами, ценами, остатками, планом и
юнит-экономикой. Интеграций с API маркетплейсов нет: все данные приходят файлами.
Главный ключ товара — артикул продавца (`util.canon_article`), а не SKU площадки.

Стек: Python 3.12 + FastAPI + psycopg3 (пул), PostgreSQL 17 (Yandex Cloud Managed,
порт 6432 через PgBouncer, БД `avtoprofi`), фронтенд — чистый JavaScript без сборщика.

## Как работать с владельцем

- Всё на русском: ответы, комментарии в коде, сообщения коммитов, документация.
- «Пока обсуждаем», «код не меняй» означают только диагностику, без правок.
- Перед правкой коротко сказать, что именно будет изменено.
- Не менять то, о чём не просили. Ничего не добавлять от себя.
  Не предлагать повторно отвергнутое (`docs/decisions.md`).
- Задача по дизайну не даёт права менять расчёты, API или состав товаров.
  Если без этого не обойтись — сначала спросить. Макеты строить по реальному интерфейсу.
- Тема только светлая. Цвета подбирать аккуратно (`docs/design.md`).
- Расследовать по фактам в коде и БД, а не по памяти. Старая запись в docs
  или старый пункт бэклога — не доказательство текущего состояния.
- Перед словом «готово» — проверка в браузере со скриншотом, а не только через API/БД.
  Явно говорить, что проверено, а что нет.
- После согласованной доработки: проверки → выкладка → бэкап кода на Google Диск
  → обновление docs. Выкладка — только после явного «да» владельца.

## Данные и безопасность — жёсткие правила

- **Рабочая БД — только чтение**, отдельным read-only подключением.
  Любая запись в неё — повторная загрузка отчёта, миграция, правка данных — только
  после явного согласования: какие даты, артикулы, источник. Перед перезаписью
  сделать снимок затрагиваемых строк. После неясного таймаута операцию не повторять,
  пока не сверен результат.
- Не запускать `app.main` с рабочей БД ради проверки: на старте выполняется
  миграция `daily_pi.migrate()`.
- **Тесты — только на тестовой БД** (`autoprofi_test` или локальная `wb_price_test`).
  Часть тестов пересоздаёт таблицы. Перед запуском проверить, куда смотрит `DB_DSN`.
- Секреты (`DB_DSN`, `SECRET_KEY`, пароли, токены) никогда не попадают в код, git,
  docs и чат. Источники: окружение или `recovery/config.json` (в `.gitignore`).
- **В том же кластере и под тем же пользователем `app` работает другой рабочий
  сервис владельца — azarov_capital (личная финансовая аналитика).** Не трогать его
  объекты и данные. Никаких операций «на всю схему или базу» (`ALL TABLES IN SCHEMA`,
  `ALTER DEFAULT PRIVILEGES`, дамп или очистка всей базы) — только явный список таблиц
  АВТОПРОФИ (`recovery/schema_contract.json`). Пароль `app` не менять, настройки и
  перезапуск кластера — только по согласованию: это остановит оба сервиса.
- Отложены владельцем: сужение CORS, обновление h11, ротация старых паролей.
  Не делать этого попутно с другой задачей.

## Красные флаги бизнес-логики

Подробно — в `docs/business_rules.md`. Нарушение любого из этих правил уже приводило
к ошибкам в данных.

- Проценты (СПП, выкуп, CR, CTR, все `*_pct`) хранятся в БД **долями 0..1**.
  Масштаб не угадывать по величине числа — смотреть формат ячейки и правила загрузчика.
- **NULL ≠ 0.** Прочерк — «нет данных», 0 — реальный ноль. Не переносить вчерашнее
  значение на пустое сегодня в дневных срезах.
- Есть **три разных Pi**: Pi кабинета площадки, «Базовая цена, Pi»
  и «Pi покупатель». «Pi покупатель» всегда = Ozon / WB, одинаков в обоих РНП.
  Итог периода — срез на конец (`daily_pi.month_end`), не среднее дневных значений.
- Прямые ценовые отчёты WB/Ozon не перезаписываются данными РНП.
  У Ozon загружаемая цена берётся «после акций», а не «Наша цена».
- **Статус, менеджер и ссылка хранятся отдельно по маркетплейсу** (`catalog_marketplace`).
  Категории L1–L3 общие (`catalog_items`). Смена статуса меняет только выбранный МП.
- Общий склад 1С (`stock_daily`) только дополняет товары, уже попавшие в РНП,
  но не добавляет новых. Неполный текущий день допустим.
- Ozon `promo_total` хранится со знаком минус. Прибыль WB уже включает рекламу —
  повторно её не вычитать. Общие удержания Ozon (`noart_exp`) — только в корне дерева.
- Перегруженные имена в РНП (`rnp_sales_router`): ключ метрики `stock_ozon_qty` —
  «остаток МП» для любой площадки (в БД у WB/Яндекса это `stock_wb_qty`/`stock_ya_qty`),
  `delivery_time_hours` — «Количество отзывов» (у Ozon так называется и колонка БД).

## Как вносить изменения

- **Загрузчики:**
  - колонки искать по имени заголовка, не по позиции;
  - писать в БД пакетно (`execute_values`, `UPDATE … FROM (VALUES …)`), а не построчно;
  - при перезаписи дня сохранять поля других загрузчиков (`PRESERVE_COLS`);
  - каждую загрузку фиксировать в `report_uploads`;
  - после записи сбросить кэш нужных namespace (`cache.bump`) — отдельно для Ozon, WB и Яндекса.
- **Фронтенд:**
  - править только `static/` и `templates/index.html`;
  - после правки JS/CSS обновить `?v=YYYYMMDDHHMM`, иначе браузеры сотрудников держат старый код;
  - пока жив хостинг Perplexity — `python3 rebuild_index.py` пересобирает `dist/public`.
- **Схема БД:** новая версионная миграция по образцу `daily_pi.migrate()`
  (advisory lock + запись в `app_schema_migrations`). Применение к рабочей БД — только по согласованию.
- **Зависимости:** при изменении `requirements.txt` обновить `recovery/requirements.lock`,
  `recovery/wheels` и `recovery/requirements-source.sha256`, иначе сборка бэкапа остановится.

## Команды

Локальное окружение на Mac ещё не настроено (нужен Python 3.12): это задача 2 в `docs/operations.md`.

```sh
# Тесты — ТОЛЬКО с DB_DSN тестовой БД и тестовым SECRET_KEY
PYTHONPATH=.:tests pytest -q tests

# Запуск приложения
DB_DSN=... SECRET_KEY=... python -m uvicorn app.main:app --port 8000

# Проверка комплекта восстановления (Linux x86_64 + Python 3.12)
python3.12 recovery/run.py --check
```
