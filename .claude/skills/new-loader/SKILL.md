# Загрузчик отчёта

Сначала прочитай `docs/data_sources.md` (реестр) и правила из раздела
«Красные флаги» в `CLAUDE.md`. Образец простого дневного загрузчика:
`app/wb_reviews_loader.py` + `upload_wb_reviews` в `app/routers/upload_router.py`.

## 1. До кода — согласовать с владельцем

- Нужен **реальный файл** отчёта (не описание). Без него не начинать.
- Уточнить: какой раздел/метрики он наполняет, есть ли дата в файле или её задают
  в форме, перезаписывает он период или дополняет, кто грузит (admin или все).
- Если колонка уже наполняется другим загрузчиком — какой источник главный.
- Сказать владельцу, что будет изменено, и дождаться «да».

## 2. Разбор файла

- Открывать образец только для чтения, из папки вне проекта, `python3 -I`.
- Колонки искать **по имени заголовка**, не по позиции (`_build_colidx`).
  Учесть варианты названий (алиасы, как `OZ_NAME_ALIASES` в `loader_core.py`).
- Файлы 1С/WB часто ломают openpyxl (`SharedStrings.xml` с заглавной S) —
  читать через `python_calamine`, как в `wb_reviews_loader._read_sheet`.
- Проценты: определить масштаб по формату ячейки Excel и документу источника,
  **не по величине числа**. В БД — доли 0..1 (`wb_reviews_loader._to_spp`).
- Пустая ячейка → NULL, не 0. Ноль из файла → 0.
- Артикул нормализовать `util.canon_article`. Неизвестные артикулы —
  считать и вернуть в ответе (`skipped_not_in_catalog`), не создавать молча,
  если владелец не решил иначе.

## 3. Запись в БД

- Сигнатура как у остальных: `load_xxx(conn, path, report_date=None) -> dict`
  с ключом `ok` и счётчиками (`rows_loaded`, `updated`, `inserted`, `file_total`, …).
- Журнал: строка в `report_uploads` со своим `period_kind`; статус OK/ОШИБКА.
  Автор подставится сам — эндпоинт вызывает `_set_uploader(conn, user)`.
- Только пакетная запись (`UPDATE … FROM (VALUES …)`, `executemany`) — построчные
  запросы к облачной БД дают таймауты 524.
- Перезапись диапазона дат: сохранить поля других загрузчиков (`PRESERVE_COLS`
  в `ozon_daily_loader`/`wb_daily_loader`). Повторная загрузка того же файла
  должна давать тот же результат (идемпотентность).
- Новая колонка/таблица → версионная миграция (см. `daily_pi.migrate`),
  применение к рабочей БД — отдельно и только по согласованию.

## 4. Эндпоинт и интерфейс

- `@router.post("/<name>")` в `upload_router.py` по образцу `upload_wb_reviews`:
  временный файл → `psycopg.connect` → `_set_uploader` → загрузчик → 422 при ошибке.
- Права: `auth.require_admin` или `auth.get_current_user` — как решил владелец.
- После успешной записи — `cache.bump(...)` нужного namespace
  (Ozon/WB/Яндекс отдельно; общий склад сбрасывает все три).
- Новый `period_kind` добавить в фильтры журнала `history` и в подписи
  журнала во `views.js`.
- Фронтенд: метод в `static/js/api.js`, форма загрузки в `static/js/views.js`;
  обновить `?v=` у изменённых файлов.

## 5. Проверка

- Тест в `tests/` на реальный образец (или минимальную копию его структуры):
  разбор, масштаб процентов, NULL vs 0, повторная загрузка.
- Тесты только на тестовой БД (`DB_DSN` с `autoprofi_test` прямо в команде).
- Загрузить образец через интерфейс на тестовой БД, открыть раздел, сделать
  скриншот, сверить 3–5 значений с Excel вручную.
- Обновить `docs/data_sources.md`.
