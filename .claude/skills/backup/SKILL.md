# Бэкап кода на Google Диск

Владелец требует полную копию кода после каждой доработки: из архива должен
подниматься весь сайт, достаточно подключить БД. Копии БД на Диск не нужны.

## Шаги

1. Тесты прошли (команда в `CLAUDE.md`), изменения закоммичены и отправлены
   на GitHub (`git push` — с подтверждением владельца).
2. Запустить (основное — копия на Mac владельца, решение 08.10.2026):
   ```sh
   bash backup_to_drive.sh --local   # → ~/AUTOPROFI_backups/code/
   bash backup_to_drive.sh           # дополнительно на Google Диск, пока rclone работает
   ```
   Скрипт остановится, если в git есть незакоммиченные правки.
   Он собирает архив через `recovery/build_backup.py`: allowlist, SHA-256-манифест,
   без секретов и без `docs/archive/perplexity_export_*`.
   Затем загружает архив в папку `autoprofi_backups` на Google Диске и сверяет MD5.
3. Сообщить владельцу имя файла и что MD5 совпал. Старые копии не удалять
   без его разрешения.

## Если что-то не так

- **`requirements.txt` изменился:** сборщик остановится. Нужно обновить
  `recovery/requirements.lock`, `recovery/wheels` (Linux x86_64, Python 3.12)
  и `recovery/requirements-source.sha256`, затем проверить восстановление.
- **Ошибка авторизации rclone** (remote `gdrive`, scope `drive.file`). Владелец
  заново входит в Google: `rclone config reconnect gdrive:` — откроется браузер.
  Файл `~/.config/rclone/rclone.conf` не читать: в нём токен.
- **Общий client_id rclone** Google отключает в 2026 году. Если загрузка перестала
  работать, нужен собственный OAuth client_id владельца (`docs/backlog.md`).
- **Проверить архив вручную:**
  1. Распаковать в пустую папку.
  2. Сверить `BACKUP_MANIFEST.json`.
  3. Прогнать тесты из распакованной копии на локальной `wb_price_test`.

## Копии базы

Ежедневная копия базы на Mac делается сама (`deploy/mac/backup-db.sh`, launchd).
После доработки проверить, что она работает: `tail ~/AUTOPROFI_backups/db/backup.log`.
Если в журнале ошибки — разобраться: нет доступа к БД, сменился хост, нет прав.
