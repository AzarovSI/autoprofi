# Выкладка доработки

Выкладка — только после явного «да» владельца на конкретное изменение.
«Пока обсуждаем» и «код не меняй» — не выкладывать.

## 1. Перед выкладкой

- Тесты на локальной `wb_price_test` (команда в `CLAUDE.md`), все зелёные.
  Новое поведение — новым тестом.
- Сайт запущен локально на `autoprofi_test` (копия рабочих данных), изменённые
  разделы пройдены в браузере (Playwright), скриншоты просмотрены глазами,
  ошибок JS и 4xx/5xx нет. Владельцу показать результат, если это видимая правка.
- Копия в `autoprofi_test` устарела? Обновить по `docs/operations.md`
  («Тестовая облачная БД») и заново создать QA-администратора.
- Изменение схемы БД? Сначала отдельно согласовать миграцию: на рабочей БД она
  выполняется от `app` (владелец таблиц), только по таблицам `public`.

## 2. Выкладка

```sh
git status                 # всё закоммичено
git push origin main       # с подтверждением владельца
bash deploy/deploy.sh      # сервер сам откатится, если /health не ответит
```

## 3. После выкладки

- Проверить https://51.250.30.154:
  - `/health`;
  - главная отдаёт новые метки `?v=` у изменённых файлов;
  - `sudo journalctl -u autoprofi -n 50` без ошибок.
- Если что-то не так: `bash deploy/deploy.sh --rollback` и сообщить владельцу.
- Бэкап: скил `backup` (`bash backup_to_drive.sh`).
- Обновить docs, если поменялись правила: `business_rules.md`, `decisions.md`,
  `backlog.md`, `history.md`.
- Сообщить владельцу:
  - что выложено;
  - что проверено и что нет;
  - имя бэкапа.
