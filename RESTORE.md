# Восстановление ТД АВТОПРОФИ

Этот архив содержит весь код приложения, исходный интерфейс, готовую сборку,
миграции, тесты, служебные скрипты, закреплённые Python-зависимости и их
установочные пакеты. Для запуска не нужны Perplexity, исходный чат, Google
Drive API, Node.js или сборка JavaScript. Google Диск служит только хранилищем ZIP.

## Требования

- Linux x86_64 с glibc 2.28+, Python 3.12 с модулями venv/ensurepip. Проверяется
  на Python 3.12.13. На Debian/Ubuntu может потребоваться пакет python3.12-venv.
- Доступная существующая PostgreSQL с полной структурой и данными сайта.
  База резервируется отдельно. Пустая новая база вместо восстановленной не подходит.
- Сетевой доступ от сервера к PostgreSQL, действующие учётные данные и SSL.
  Все Python-пакеты для указанной платформы находятся в recovery/wheels;
  интернет для их установки не нужен. ОС и интерпретатор в ZIP не входят.

## Быстрый запуск

Распакуйте архив. Откройте папку avtoprofi_app.

```sh
cp recovery/config.example.json recovery/config.json
```

В recovery/config.json заполните только DB_DSN. Пример синтаксиса:

```json
{
  "DB_DSN": "host=YOUR_DB_HOST port=6432 dbname=YOUR_DB user=YOUR_USER password=YOUR_PASSWORD sslmode=require",
  "HOST": "127.0.0.1",
  "PORT": 8000,
  "TOKEN_TTL_HOURS": 24
}
```

Это шаблон, не реальные реквизиты. Сохраните правильное JSON-экранирование.
Порт и SSL возьмите из настроек вашей БД; 6432 не универсален.
Для sslmode=verify-full дополнительно настройте доверенный sslrootcert.
Не отправляйте заполненный config.json другим людям.

```sh
python3.12 recovery/run.py --check
python3.12 recovery/run.py
```

Первая команда проверяет целостность архива, создаёт изолированное окружение,
устанавливает пакеты без доступа к PyPI и проверяет БД только на чтение.
Вторая запускает сайт: http://127.0.0.1:8000.
Для входа используйте существующих пользователей и пароли из вашей БД.
Проверка связи: http://127.0.0.1:8000/health.

Запуск самого приложения сохраняет существующую логику: проверяет миграцию
daily Pi и при необходимости применяет её. Скрипт не пересоздаёт и не очищает
БД. На актуальной восстановленной БД миграция уже отмечена выполненной.
Нужны те же права БД, что у действующего приложения.

## Ключ авторизации

При первом запуске создаётся случайный ключ в recovery/runtime/secret.key
с правами 0600. Повторный запуск использует тот же ключ.
Старые сессии не переносятся: пользователи входят заново, пароли и роли
остаются в БД. Вместо автогенерации можно безопасно передать SECRET_KEY
через окружение. Рабочий ключ и пароль БД в архив не включаются.
Храните каталог runtime между перезапусками.

## Публичный адрес и постоянная работа

Для постоянной работы запустите команду через менеджер служб вашей ОС.
Сайт обслуживает интерфейс и API на одном порту; reverse proxy должен
перенаправлять все пути, включая /api и /static, без изменений на 8000.
Разместите HTTPS-прокси перед приложением, настройте DNS своего домена.
Сам архив не переносит домен, TLS-сертификат и настройки внешнего хостинга.
Не публикуйте каталог проекта как папку статических файлов.
Секреты и исходники не должны раздаваться веб-сервером.

На обычном домене frontend обращается прямо к /api. Для *.pplx.app
сохранена платформенная схема /port/8000. Возврат именно на autoprofi.pplx.app
требует доступа к публикации Perplexity; независимый запуск такого доступа не требует.

## Docker как альтернативный способ

Dockerfile.restore и compose.restore.yml дают дополнительный шаблон:

```sh
docker compose -f compose.restore.yml up -d --build
```

Сначала создайте config.json. Первый запуск Docker требует скачивания базового
образа Python; зависимости приложения берутся из архива. Этот способ в текущей
среде не проверен: Docker отсутствует. Проверенный способ — Python 3.12 выше.
Не удаляйте volume recovery-runtime: он хранит ключ авторизации.

## Проверка полноты

BACKUP_MANIFEST.json содержит SHA-256 каждого включённого файла, платформу
и дату создания. run.py проверяет их до запуска. В архив включены все файлы
app, static, templates, dist, migrations, tests, recovery (кроме runtime/config),
requirements.txt, rebuild_index.py, migrate_incidents.py и скрипт бэкапа.
Сырые старые handoff-документы не включены: они содержали секреты. Вместо них
даны безопасные RESTORE.md и HANDOFF_RECOVERY.md.

БД, реальные ключи, .git, Python-кэши, старые загруженные отчёты и временные
скриншоты в комплект не входят. Рабочие данные приложения находятся в PostgreSQL,
а не в этих исключённых файлах. Не запускайте tests против рабочей БД:
часть тестов пересоздаёт таблицы в отдельной локальной wb_price_test.

## Следующие резервные копии

```sh
bash backup_to_drive.sh --output /path/to/private/backups
```

Скрипт упакует текущий код и всё окружение восстановления; загрузка готового
ZIP на Google Диск выполняется отдельно. Не используйте старую команду
архивирования всего каталога: она может захватить конфигурацию с паролем.
Если requirements.txt изменился, сборщик остановится до обновления lock,
wheels и повторной проверки восстановления.

Рабочий сайт и его requirements.txt не менялись. Для восстановления версии
зависимостей разрешены из этого requirements.txt, закреплены с SHA-256 и
проверены отдельно. Архив фиксирует проверенное окружение, а не заменяет
плановое обслуживание зависимостей.
