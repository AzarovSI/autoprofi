# Структура базы данных АВТОПРОФИ

`schema_public_20261007.sql` — точный снимок структуры схемы `public` рабочей БД
на 07.10.2026: 31 таблица с типами и ограничениями, 44 индекса, 3 функции и
12 триггеров дневного Pi, счётчики id. Данных нет.

Источник снимка: `pg_dump -n public --schema-only --no-owner --no-privileges`
пользователем `autoprofi_ro`. Строки `CREATE SCHEMA public` и `COMMENT ON SCHEMA`
убраны, чтобы файл разворачивался в любую новую базу.

**Почему не из кода.** Часть изменений схемы Perplexity делал вручную, и в
`migrations/` их нет. Код описывает схему не полностью, источник истины — этот файл.

**Проверено.** 07.10.2026 файл развёрнут в пустую `autoprofi_test` без ошибок.
Затем туда перенесены данные, и сайт полностью работал на этой копии.

## Восстановление с нуля (если рабочая БД потеряна)

1. Создать базу и пользователей:
   - база, например `avtoprofi`;
   - пользователь-владелец;
   - пользователь сайта.

   Подробности — `docs/operations.md`.
2. Развернуть структуру:
   ```sh
   psql "<подключение владельцем>" -v ON_ERROR_STOP=1 -f db/schema_public_20261007.sql
   ```
3. Служебные записи, без которых сайт не стартует (`recovery/check_database.py`):
   ```sql
   INSERT INTO app_schema_migrations (name) VALUES ('2026_09_21_daily_pi');
   INSERT INTO price_index_revision (singleton, revision) VALUES (true, 0);
   ```
4. Первый администратор: строка в `app_users` с bcrypt-хешем пароля и ролью `admin`.
   Хеш — `app.auth.hash_password`.
5. Права пользователю сайта: SELECT/INSERT/UPDATE/DELETE на 31 таблицу, USAGE/SELECT
   на 14 счётчиков, USAGE/CREATE на схему. Список — в `docs/operations.md`.
6. Данные:
   - **из ежедневной копии**, если она есть: `pg_restore` в эту структуру;
   - **без копии** — загрузить отчёты заново через сайт и заполнить вручную то,
     чего в отчётах нет. Это справочник товаров (категории, статусы, менеджеры, ссылки),
     базовые цены, себестоимость, планы продаж, склады (переименования, объединения,
     инциденты), правила аномалий, комментарии РНП, пользователи.

## Обновлять снимок

После любой миграции, меняющей схему, снять снимок заново (`autoprofi_ro`,
команда выше) и сохранить с новой датой.
